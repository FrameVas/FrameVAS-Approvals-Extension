Approvals Lite додає до EspoCRM новий тип поля — **Погодження** (Approves). Додайте його до будь-якої сутності — документів, переведень, договорів, заявок — оберіть, хто має погодити кожен запис, і погоджувачі зможуть погодити або відхилити його одним кліком. Поле зберігає кожне рішення, вчасно сповіщає потрібних людей і показує загальний статус погодження, який можна використовувати у списках, фільтрах, Kanban, робочих процесах, формулах і шаблонах PDF.

## Можливості

- **Тип поля «Погодження»** — додається до будь-якої сутності в Менеджері сутностей, як і будь-яке інше поле.
- **Два режими погодження** — *Паралельно* (усі погоджують у будь-якому порядку) або *Етапи* (етап 2 починається лише після того, як погодили всі учасники етапу 1).
- **Кнопки «Погодити» / «Відхилити»** — показуються лише користувачу, чия зараз черга, з можливістю додати коментар.
- **Поле загального статусу** — `Pending` (Очікує), `Approved` (Погоджено) або `Declined` (Відхилено), створюється автоматично; доступне у фільтрах, Kanban, звітах, робочих процесах і BPM.
- **Сповіщення** — погоджувачі отримують сповіщення, коли настає їхня черга; власник запису — про кожне рішення.
- **Журнал аудиту в Потоці** — зрозумілі записи про кожне рішення та кожну зміну списку погоджувачів.
- **Фільтр пошуку** — пошук записів за погоджувачем, за рішенням або «очікує мого рішення».
- **Відображення у списку** — лічильник (`1/3 Очікує`), кольорові імена погоджувачів або обидва варіанти.
- **Шаблони PDF** — готовий текст, таблиця, налаштовувана таблиця та дані для циклів.
- **Підтримка формул** — читання погоджувачів, етапів і рішень у скриптах формул.
- **Захист** — користувачі не можуть підробити рішення; рішення фіксується лише через дію «Погодити/Відхилити» і лише самим погоджувачем.
- **Переклади** — англійська та українська мови вже включені; інші мови легко додати.

## Вимоги

- EspoCRM 9.0 або новіша (перевірено на EspoCRM 10)
- PHP 8.3 або новіша

## Встановлення

1. Завантажте останній пакет розширення (`.zip`) зі сторінки [Releases](../../releases).
2. В EspoCRM перейдіть до **Адміністрування → Розширення**.
3. Натисніть **Завантажити**, виберіть завантажений файл і натисніть **Встановити**.
4. Відкрийте **Адміністрування → Очистити кеш**.
5. Оновіть сторінку в браузері.

### Оновлення з попередньої версії «Approvals»

Якщо у вашій системі встановлено ранній пакет з назвою **Approvals**, просто встановіть цей пакет поверх нього. Інсталятор автоматично перейме запис старого розширення і збереже всі ваші дані.

> ⚠️ **Не натискайте «Видалити» для старого розширення «Approvals».** Обидва пакети використовують ті самі файли, тож видалення старого пакета видалить і їх.

## Швидкий старт

1. **Додайте поле.** Відкрийте **Адміністрування → Менеджер сутностей → *ваша сутність* → Поля → Додати поле**, оберіть тип **Погодження**, вкажіть мітку та збережіть. EspoCRM додає префікс `c` до назв власних полів, тож поле `approves` отримає назву `cApproves`. Друге поле, **Approves Status** (`cApprovesStatus`), створюється автоматично.
2. **Додайте поле до макетів.** У розділі **Макети** додайте поле до *Детального перегляду* (та за потреби до *Списку*, *Полів бічної панелі* і *Фільтрів пошуку*). Додайте також поле статусу, якщо хочете бачити загальний результат або фільтрувати за ним.
3. **Надайте доступ.** Погоджувачам потрібен лише доступ на **читання** сутності в їхніх ролях. Для друку PDF користувачам потрібен також доступ на читання **Шаблонів PDF**.
4. **Користуйтеся.** Відкрийте запис у режимі редагування, натисніть **Додати погоджувача**, оберіть користувачів і збережіть. Погоджувачі отримають сповіщення і зможуть погодити або відхилити запис.

## Параметри поля

| Параметр | Опис |
|---|---|
| **Обов'язково** | Потрібно додати хоча б одного погоджувача. |
| **Режим погодження** | **Паралельно** — усі погоджувачі можуть діяти одночасно, у будь-якому порядку. **Етапи** — погоджувачі розподілені за етапами; етап починається, коли всі учасники попереднього етапу погодили. |
| **Приховати коментар при погодженні** | Погодження лише запитує підтвердження, без поля для коментаря. |
| **Приховати коментар при відхиленні** | Відхилення лише запитує підтвердження, без поля для коментаря. |
| **Розташування кнопок «Погодити/Відхилити»** | **Під списком погоджувачів** (за замовчуванням), **Над списком погоджувачів** або **Заголовок запису** (біля кнопки «Змінити»). |
| **Відображення у списку** | **Підсумок** (`1/3 Очікує`), **Погоджувачі** (кольорові імена) або **Підсумок + погоджувачі**. |
| **Аудит** | Записує рішення та зміни списку погоджувачів у Потік запису. |
| **Лише для читання** | Стандартний параметр EspoCRM. Рішення все одно можна ухвалювати. |
| **Тільки для читання після створення** | Список погоджувачів можна задати лише під час створення запису, потім він блокується. Рішення все одно можна ухвалювати, а формули, робочі процеси та BPM можуть змінювати список. |

## Як працює погодження

- **Режим «Паралельно»** — кожен погоджувач може погодити або відхилити запис у будь-який момент.
- **Режим «Етапи»** — діяти можуть лише погоджувачі поточного етапу. Наступні етапи мають позначку *Очікує черги* і отримують сповіщення, коли настає їхній етап. У режимі редагування використовуйте **Додати етап** і стрілки ↑ ↓, щоб розподілити погоджувачів.
- **Одне відхилення** на будь-якому кроці робить загальний статус *Відхилено* і зупиняє процес.
- **Коли всі погодили**, загальний статус стає *Погоджено*.
- **Хто може діяти** — лише погоджувач, чия зараз черга, і лише за себе. Погоджувачам достатньо доступу на читання запису.
- **Редагування списку** — користувачі, які можуть редагувати запис, можуть додавати, видаляти та переміщати погоджувачів. Уже ухвалені рішення завжди зберігаються. Щоб скинути чиєсь рішення, видаліть погоджувача, збережіть і додайте його знову.
- **Статуси на сторінці запису** — кожен погоджувач має кольорову мітку (зелена *Погоджено*, помаранчева *Очікує*, червона *Відхилено*, сіра *Очікує черги*), дату рішення та коментар. У режимі «Етапи» кожен етап позначено як *Завершено*, *Поточний* або *Очікує черги*.

## Сповіщення

- Коли настає черга погоджувача, він отримує сповіщення **«Потрібне ваше погодження: …»**.
- Коли хтось погоджує або відхиляє запис, сповіщення отримує **відповідальний користувач** запису (або його автор).
- Сповіщення пишуться мовою кожного отримувача.

## Журнал аудиту (Потік)

Якщо увімкнено параметр **Аудит** (і для сутності увімкнено Потік), у Потоці відображаються:

- **Рішення** — «Bob погодив цей запис», з етапом і коментарем.
- **Зміни списку погоджувачів** — додані, видалені та переміщені погоджувачі (наприклад, *Переміщено: Carol: Етап 1 → Етап 2*).

Для загального результату можна також увімкнути стандартний параметр EspoCRM **Аудитоване** для поля статусу, щоб фіксувати зміни *Очікує → Погоджено*.

## Фільтр пошуку

Додайте поле «Погодження» до **Макети → Фільтри пошуку**. У списку відкрийте меню фільтрів, оберіть поле та умову:

| Умова | Показує записи, де… |
|---|---|
| **Містить будь-кого з** | хоча б один з обраних користувачів є погоджувачем |
| **Містить усіх** | усі обрані користувачі є погоджувачами |
| **Не містить** | жоден з обраних користувачів не є погоджувачем |
| **Погоджено користувачем** / **Відхилено користувачем** | обраний користувач ухвалив таке рішення |
| **Очікує рішення від** | зараз черга обраного користувача |

Кнопка **Я** додає поточного користувача. **Очікує рішення від → Я** + **Зберегти фільтр** дає кожному користувачу власний список «очікує мого погодження».

> Поле швидкого пошуку шукає лише текстові поля; для пошуку за погоджувачами використовуйте фільтр.

## Kanban

Укажіть поле статусу погодження як **Поле статусу** сутності в Менеджері сутностей, щоб згрупувати записи в колонки *Очікує*, *Погоджено* і *Відхилено*. Назви колонок перекладаються автоматично; їх можна змінити в **Менеджері міток**.

## Формули

У скриптах формул значення поля — це список погоджувачів. Кожен погоджувач — об'єкт з такими ключами:

| Ключ | Значення |
|---|---|
| `id` | ID користувача |
| `name` | ім'я користувача |
| `stage` | номер етапу (у режимі «Паралельно» завжди `1`) |
| `status` | `Pending`, `Approved` або `Declined` |
| `resolvedAt` | дата й час рішення, порожньо, поки рішення немає |
| `comment` | коментар до рішення, якщо є |

Загальний результат зберігається в атрибуті `cApprovesStatus`.

**Приклад — реакція на остаточний результат:**

```
if (cApprovesStatus == 'Approved' && entity\isAttributeChanged('cApprovesStatus')) {
    description = string\concatenate(description, '\nПогоджено всіма');
}
```

**Приклад — перевірка, чи всі погоджувачі етапу 1 погодили:**

```
$items = cApproves;
$i = 0;
$total = 0;
$approved = 0;

while ($i < array\length($items)) {
    $item = array\at($items, $i);

    if (object\get($item, 'stage') == 1) {
        $total = $total + 1;

        if (object\get($item, 'status') == 'Approved') {
            $approved = $approved + 1;
        }
    }

    $i = $i + 1;
}

if ($total > 0 && $approved == $total) {
    // Етап 1 завершено.
}
```

**Приклад — додати учасників команди як погоджувачів етапу 1 до нових записів:**

```
if (entity\isNew()) {
    $teamId = record\findOne('Team', null, null, 'name=', 'Director');

    if ($teamId) {
        $userIds = record\findRelatedMany('Team', $teamId, 'users', 100, 'userName', 'asc', 'isActive=', true);
        $list = cApproves;

        if (!$list) {
            $list = list();
        }

        $i = 0;

        while ($i < array\length($userIds)) {
            $item = object\create();
            object\set($item, 'id', array\at($userIds, $i));
            object\set($item, 'name', record\attribute('User', array\at($userIds, $i), 'name'));
            object\set($item, 'stage', 1);
            object\set($item, 'status', 'Pending');
            $list = array\push($list, $item);
            $i = $i + 1;
        }

        cApproves = $list;
    }
}
```

Розширення не дублює користувачів, які вже є у списку, а нові погоджувачі завжди починають зі статусу *Очікує*.

## Шаблони PDF

Розширення автоматично додає дані про погоджувачів до **Шаблонів PDF**. Тексти друкуються мовою користувача, який друкує документ, дати — у його часовому поясі.

| Заповнювач | Результат |
|---|---|
| `{{cApproves}}` | Текст: *Bob (Погоджено), Carol (Очікує)* |
| `{{cApprovesStatus}}` | Загальний статус |
| `{{{cApprovesTable}}}` | Готова таблиця (зверніть увагу на **три** фігурні дужки) |
| `{{approvesTable cApprovesList columns="…"}}` | Таблиця з обраними колонками |
| `{{#each cApprovesList}}…{{/each}}` | Цикл по погоджувачах |

### Налаштовувана таблиця

```
{{approvesTable cApprovesList columns="stage,approver,title,status,date"}}
{{approvesTable cApprovesList columns="number,approver:ПІБ,title,signature"}}
{{approvesTable cApprovesList columns="approver,emailAddress,phoneNumber,status"}}
```

| Колонка | Показує |
|---|---|
| `number` | номер рядка |
| `stage` | номер етапу (у режимі «Паралельно» прихована) |
| `approver` | ім'я користувача |
| `title` | посаду користувача (поле «Title») |
| `status` | рішення (перекладене) |
| `date` | дату рішення |
| `comment` | коментар до рішення |
| `signature` | порожню клітинку для підпису |
| *будь-яке поле користувача* | наприклад, `emailAddress`, `phoneNumber`, `gender`, `teams`, `defaultTeam` або власні поля, як-от `cDepartment` |

- Заголовок колонки можна змінити так: `ключ:Заголовок`, наприклад `approver:ПІБ`.
- Колонки, у яких усі значення порожні, приховуються автоматично; додайте `hideEmpty="false"`, щоб завжди їх показувати.
- Невідомі назви колонок пропускаються, тож помилка в назві не зламає PDF.

### Значення в циклі

Усередині `{{#each cApprovesList}}`: `name`, `title`, `status`, `statusRaw`, `stage`, `stageLabel`, `resolvedAt`, `comment`, а також прапорці `isApproved`, `isDeclined`, `isPending`, `isWaiting`.

> Порада: розміщуйте цикли поза HTML-таблицями або використовуйте налаштовувану таблицю — редактор шаблонів переміщує теги `{{#each}}`, розміщені між рядками таблиці.

### Приклад шаблону

```html
<h2>{{name}}</h2>
<p><b>Статус погодження:</b> {{cApprovesStatus}}</p>
<p><b>Погоджувачі:</b> {{cApproves}}</p>

<h3>Лист погодження</h3>
<div>{{approvesTable cApprovesList columns="stage,approver,title,status,date,comment"}}</div>

<h3>Підписи</h3>
<div>{{approvesTable cApprovesList columns="number,approver,title,signature"}}</div>
```

## API

Рішення фіксуються через окрему кінцеву точку:

```
POST /api/v1/Approves/{entityType}/{id}/{field}/resolve

{"action": "approve", "comment": "Необов'язковий текст"}
```

`action` — `approve` або `decline`. Запит приймається лише від погоджувача, чия зараз черга. У відповіді повертаються оновлене значення поля та загальний статус.

## Переклади

Англійська та українська мови вже включені. Щоб додати мову, скопіюйте `custom/Espo/Modules/Approvals/Resources/i18n/en_US` у папку з кодом мови EspoCRM (наприклад, `de_DE`), перекладіть значення (ключі та заповнювачі, як-от `{user}`, залиште без змін) і очистьте кеш.
